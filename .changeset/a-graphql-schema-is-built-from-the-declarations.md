New package `@etherfold/graphql` (ADR-0099): `buildQuerySchema(declarations)` builds ONE GraphQL schema from the entity declarations with Pothos over graphql-js, an object type per entity, a nested collection per declared relation (read for a page of parents in one batched accessor call, bounded per parent), enums as GraphQL enums, `u256` as a `U256` scalar carried as a decimal string, `integer` as `SafeInt` and `blob` as `Bytes` (`0x` hex); each entity's root list field and every nested collection take `where` (per column, with `_and` / `_or`), `orderBy` and a required `first`, and a root field takes `block`. The resolvers call the accessor seam only. `executeQuery` / `localExecutor(schema, context)` run it in process: every operation pins the tip as its block, reads every field as of it, and reports `{generation, block}` in `extensions`; a reorg that takes the tip below the pin is retried once and then refused (`tip-moved-during-operation`). One error formatter (`formatQueryError`) and one set of codes (`QUERY_ERROR_CODES`). The `QueryExecutor` contract is defined here, with the one transport-failure shape every executor normalises to (`transportFailure`, `isTransportFailure`, `TRANSPORT_FAILURE_REASONS`). The root entry imports nothing runtime-specific and builds for Node and for a browser.
