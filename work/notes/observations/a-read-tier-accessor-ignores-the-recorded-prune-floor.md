# A read tier's accessor ignores the prune floor recorded in the database

Observed 2026-09-28 while building `a-server-answers-graphql-over-http`: `VersionedStateStore.accessor()` (`packages/state-store-sqlite/src/store.ts`) checks an as-of read with `assertRetained(this.capabilities, ...)`, which knows only the retention THIS handle was configured with. `retainedFrom()` beside it also reads the floor a prune pass recorded (`retentionEnforcement`), and `producePublication` uses that. So `etherfold serve`, which opens the database with no retention of its own (`unbounded`), answers a GraphQL `block:` below a floor the writer's `--retention` already pruned from partly-deleted history instead of refusing it with `block-not-retained`. `run` / `node` / `index` pass their own retention to `/graphql` and are not affected.
