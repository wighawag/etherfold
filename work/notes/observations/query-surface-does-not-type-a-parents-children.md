# The SQLite query surface carries a parent's children at run time but not in its type

Observed 2026-09-28 while building `the-read-surface-offers-a-parents-children`: `createQuerySurface` in `packages/state-store-sqlite/src/query-surface.ts` spreads `createReadSurface`'s per-entity reads, so a declared relation's collection (`surface.placement.players`) is present at run time, but its `EntityQueries<E>` type is `EntityReads & {queryCurrent, queryAsOf}` and does not include `CollectionsOf`, so a consumer cannot reach it without a cast. Also, `READ_SURFACE_NAMES` in `packages/state-store/src/entities.ts` reserves only the four seam reads, so a child declaring `as: 'queryCurrent'` or `as: 'queryAsOf'` is accepted and its collection is silently overwritten by the query tier on that surface.
