# Importing `workerExecutor` puts the `graphql` runtime in the TAB's bundle

Observed 2026-09-28 while building `a-browser-app-queries-its-worker-with-graphql`. `examples/browser-reference/browser/main.ts` imports only `workerExecutor` from `@etherfold/graphql/worker`, yet a `vite build` of the reference grows the tab chunk from 170.7 KB (63.2 KB gzipped) to 268.3 KB (86.7 KB gzipped), and the chunk contains graphql-js (`GraphQLSchema`, `__Schema`). The subpath module (`packages/graphql/src/worker/index.ts`) also imports the handler's pipeline (`execute.js`, `schema.js`, `documents.js`), and `@etherfold/graphql`'s `package.json` declares no `sideEffects`, so the bundler keeps those modules. Adding `"sideEffects": false` there (tried, then reverted) brings the tab chunk back to 172.0 KB (63.7 KB gzipped) with no graphql in it; splitting `workerExecutor` into a module that imports only `executor.js` would do the same. This contradicts ADR-0099's "off the first-paint path" for the TAB (the worker cost is as documented), and the guide states the current tab cost until it is fixed.
