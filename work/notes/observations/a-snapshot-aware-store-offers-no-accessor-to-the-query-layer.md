# A snapshot-aware store offers no accessor to the query layer

Observed 2026-09-28 while building `a-worker-host-answers-graphql-over-its-port`. The browser query handler (`graphqlQueryHandler` in `packages/graphql/src/worker/index.ts`) reads through the store's `accessor()` and `tip()`, which `IndexedDBStateStore` has and the claimed handle (`openForWriting`, `packages/state-store/src/store.ts`) now forwards. `SnapshotAwareStateStore` (`packages/state-store/src/snapshot.ts`), which a generation bootstrapped from a published snapshot is wrapped in, forwards neither, so a host whose canonical generation started from a publication would answer every GraphQL query `internal-error`. Forwarding them naively is not obviously right either: the snapshot-aware store has its own rules for as-of reads below the snapshot's block, which an accessor read would bypass. Unverified end to end; no test covers a queried host that started from a snapshot.
