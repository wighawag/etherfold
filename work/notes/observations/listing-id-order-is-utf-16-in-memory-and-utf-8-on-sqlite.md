# The listing's id order is UTF-16 in memory and UTF-8 bytes on SQLite

Observed 2026-09-28 while building `an-accessor-finds-rows-by-a-predicate-on-sqlite`, not verified by a test: `compareIds` in `packages/state-store/src/listing.ts` (the order the memory and patch backends sort a listing by) compares id strings with JavaScript's `<`, which is UTF-16 code-unit order, while SQLite walks its TEXT id index in BINARY order (UTF-8 bytes, i.e. code-point order). The two disagree when an id holds a supplementary-plane character next to one in U+E000 to U+FFFF, so `listCurrent` could order such ids differently per backend. Ids come from event args (addresses, hashes, decimals) so it may never bite, but the accessor seam now fixes text order as UTF-8 bytes (ADR-0099), and the listing does not say which it promises.
